# Step 4: Verify Your API Routes

Make sure your API has these endpoints:

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | /tasks | Get all tasks |
| GET | /tasks/:id | Get one task |
| POST | /tasks | Create a task |
| PUT | /tasks/:id | Update a task |
| DELETE | /tasks/:id | Delete a task |

---

# Step 5: Evaluate Using Richardson Maturity Model

## Level 0
- Single endpoint for everything.
- Example:
```text
POST /api
```

## Level 1
- Separate resources.
- Example:
```text
/tasks
/users
```

## Level 2
Your API must use:
- Correct resource URLs
- Correct HTTP methods (GET, POST, PUT, DELETE)
- Correct HTTP status codes

## Level 3
Add HATEOAS links in API responses.

---

# Step 6: Check HTTP Status Codes

| Situation | Status Code |
|-----------|------------|
| Success | 200 |
| Created | 201 |
| Invalid Request | 400 |
| Not Found | 404 |
| Server Error | 500 |

Example:

```javascript
res.status(200).json(data);
res.status(201).json(data);
res.status(400).json({ message: "Invalid Data" });
res.status(404).json({ message: "Task not found" });
res.status(500).json({ message: "Internal Server Error" });
```

# Viva Questions

**Q1. What is the Richardson Maturity Model?**

A model used to measure how RESTful an API is.

**Q2. Which level is commonly used in industry?**

Level 2.

**Q3. What is HATEOAS?**

A technique where API responses include links to related actions.

**Q4. Why do most production APIs stop at Level 2?**

Because Level 2 provides a practical balance of REST principles, simplicity, and maintainability.
